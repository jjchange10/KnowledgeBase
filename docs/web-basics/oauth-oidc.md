# OAuth / OIDC

「Googleでログイン」「GitHubでサインイン」のようなボタンの裏側で動いている仕組みです。混同されがちですが、役割は次のように異なります。

- OAuth 2.0 → **「認可」のためのプロトコル**
- OIDC（OpenID Connect）→ **「認証」のためのプロトコル**

## OAuth 2.0 とは（認可）

OAuthは、「あるサービス（クライアント）が、ユーザーに代わって別のサービス（リソースサーバー）のデータにアクセスしてよい」という**許可（認可）を得るための仕組み**です。

例: カレンダーアプリが、Googleカレンダーの予定を読み取る許可をユーザーから得る場合。

```
User        Client(カレンダーアプリ)      Authorization Server(Google)      Resource Server(Google Calendar API)
 |                  |                              |                                |
 |  「連携する」を押す|                              |                                |
 |----------------->|                              |                                |
 |                  |  認可リクエスト（リダイレクト）|                                |
 |<------------------------------------------------|                                |
 |  ログイン & 許可画面で同意                        |                                |
 |------------------------------------------------->|                                |
 |                  |  認可コードを付けてリダイレクト |                                |
 |<------------------------------------------------|                                |
 |  認可コードをクライアントに渡す                    |                                |
 |----------------->|                              |                                |
 |                  |  認可コード → アクセストークン交換                              |
 |                  |----------------------------->|                                |
 |                  |  アクセストークン              |                                |
 |                  |<-----------------------------|                                |
 |                  |  アクセストークンを使ってAPI呼び出し                             |
 |                  |------------------------------------------------------------->|
 |                  |  カレンダーの予定データ                                        |
 |                  |<-------------------------------------------------------------|
```

ポイントは、カレンダーアプリは**ユーザーのGoogleパスワードを一切知らない**ことです。ユーザーはGoogleの画面上で直接ログイン・同意し、カレンダーアプリは発行された「アクセストークン」という限定的な権限の鍵だけを受け取ります。

## OIDC（OpenID Connect）とは（認証）

OAuth 2.0はあくまで「APIへのアクセス許可」の仕組みであり、本来「このユーザーが誰であるか」を証明するためのものではありません。しかし実際には「Googleでログイン」のように、OAuthの仕組みを流用してログイン機能を実装するケースが広まったため、標準化されたのがOIDCです。

OIDCはOAuth 2.0の上に、**IDトークン（JWT形式）という「このユーザーが確かに本人である」ことを証明する仕組み**を追加します。IDトークンには、発行者・対象者・ユーザーの識別子・有効期限などが署名付きで含まれており、クライアントはこれを検証することでユーザーを認証できます。

| | OAuth 2.0 | OIDC |
|---|---|---|
| 目的 | 認可（Authorization） | 認証（Authentication） |
| 答える質問 | 「このアプリはユーザーの代わりに何をしてよいか」 | 「このユーザーは誰か」 |
| 得られるもの | アクセストークン | アクセストークン + IDトークン |

## よくある誤解

「OAuthでログインしている」という表現をよく見ますが、厳密にはOAuth単体はログイン（認証）の仕組みではありません。ソーシャルログインの多くは実際にはOIDCを使っており、「OAuthでログイン」は「OIDC（を含むOAuthの拡張）でログイン」の略した言い方と考えるのが正確です。

## いつ使うか

- 自社サービスに「Googleでログイン」「GitHubでログイン」のようなソーシャルログインを実装するとき（OIDC）
- 自社アプリから、Google Drive や Slack など外部サービスのAPIに、ユーザーの代わりにアクセスしたいとき（OAuth）
- 複数の自社サービス間でシングルサインオン（SSO）を実現したいとき（OIDC）
