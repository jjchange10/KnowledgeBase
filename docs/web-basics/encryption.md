# 暗号化

「通信やデータを第三者に盗み見られても、中身が分からないようにする」ための技術です。Webの文脈では、HTTPS通信や、パスワード・個人情報の保存でほぼ必須の知識になります。

## 共通鍵暗号（対称鍵暗号）

暗号化と復号に**同じ鍵**を使う方式です（AESなどが代表例）。

```
平文 --[鍵Kで暗号化]--> 暗号文 --[鍵Kで復号]--> 平文
```

- 長所: 処理が高速
- 短所: 暗号化する側と復号する側の両方が同じ鍵を持つ必要があり、その鍵を安全にどう相手に渡すか（鍵配送問題）が課題になる

### 何が起きたか

- 暗号化のたびに新しいランダムな**IV（初期化ベクトル）が生成されています**。同じ平文・同じ鍵でも、暗号化するたびに暗号文が変わるのはこのためです。
- AES-**GCM**モードには改ざん検知の仕組み（認証タグ）が組み込まれているため、鍵が違ったり暗号文が1バイトでも改ざんされていたりすると、復号結果が文字化けするのではなく、明確に「復号エラー」として検出されます。

## 公開鍵暗号（非対称鍵暗号）

**公開鍵**と**秘密鍵**というペアの鍵を使う方式です（RSA、楕円曲線暗号（ECC）などが代表例）。公開鍵で暗号化したデータは、対応する秘密鍵でしか復号できません。

```
送信者: 受信者の公開鍵で暗号化 --> 暗号文 --> 受信者: 自分の秘密鍵で復号
```

- 長所: 公開鍵は文字どおり公開してよいため、事前に秘密の鍵を共有する必要がない
- 短所: 共通鍵暗号に比べて計算コストが高く低速

### RSAを実際に計算してみる

下のデモは、代表的な公開鍵暗号であるRSAを、実際に「手で検算できる」小さな素数で計算するものです。実際のRSAは数百桁の素数を使いますが、鍵の生成・暗号化・復号の**計算そのもの**は、ここで行っているものと全く同じ仕組みです。

<RsaDemo />

計算の流れ:

1. 2つの素数 `p`, `q` を選び、`n = p × q` を計算する（`n` が公開鍵・秘密鍵の両方に使われる「法」になる）
2. `φ(n) = (p−1)(q−1)` を計算する
3. `φ(n)` と互いに素な数 `e` を選ぶ → `(e, n)` が**公開鍵**
4. `e × d ≡ 1 (mod φ(n))` を満たす `d` を求める → `d` が**秘密鍵**
5. 暗号化: `c = m^e mod n`
6. 復号: `m = c^d mod n`

「計算過程を見る」を開くと、`m^e mod n` のような一見大変そうな計算が、指数を2進数で見て「2乗する」「元の値を掛ける」を繰り返すだけ（**繰り返し二乗法**）で計算できていることも確認できます。

秘密鍵と公開鍵の関係を逆向きに使うと**デジタル署名**になります。送信者が秘密鍵で署名し、受信者が対応する公開鍵で検証することで、「確かにこの秘密鍵の持ち主が作成した、改ざんされていないデータである」ことを確認できます。

## ハイブリッド暗号（TLSでの実際の使われ方）

HTTPS（TLS）では、公開鍵暗号と共通鍵暗号の両方の長所を組み合わせています。

1. 通信の最初に、公開鍵暗号（または鍵交換アルゴリズム）を使って、これから使う共通鍵（セッション鍵）を安全に共有する
2. 以降の実際のデータのやり取りは、高速な共通鍵暗号で暗号化する

これにより、「鍵配送問題を安全に解決しつつ、通信自体は高速に行う」ことを両立しています。

## ハッシュ関数

厳密には暗号化（＝復号できる）ではありませんが、セキュリティの文脈で必ずセットで出てくる技術です。任意の長さの入力から、固定長の値（ハッシュ値）を生成します。

- **一方向性**: ハッシュ値から元の入力を逆算することは（計算量的に）できない
- **衝突耐性**: 異なる入力から同じハッシュ値が生成されることは極めて起こりにくい

上のデモの「ハッシュ関数」タブで、文字列を1文字変えるだけでハッシュ値がまったくの別物になる**雪崩効果（Avalanche Effect）を確認できます**。また、同じパスワードでもユーザーごとに異なるソルトを加えることで、保存されるハッシュ値が変わることも確認できます。

### パスワード保存への応用

パスワードをそのままDBに保存すると、DBが漏洩した際に全ユーザーのパスワードが即座に漏洩します。そのため、パスワードは**ハッシュ化**して保存するのが基本です。

```
保存時: パスワード + ソルト --[ハッシュ関数]--> ハッシュ値 をDBに保存
検証時: 入力されたパスワード + ソルト --[ハッシュ関数]--> ハッシュ値 が一致するか比較
```

単純なハッシュ関数（SHA-256など）は計算が高速すぎるため、総当たり攻撃に弱く、パスワード保存にはそのまま使うべきではありません。**bcrypt**、**scrypt**、**Argon2**のように、意図的に計算コストを高くした（＝総当たりを困難にした）アルゴリズムを使います。また、同じパスワードでも異なるハッシュ値になるよう、ユーザーごとにランダムな**ソルト**を加えるのも重要です。

## まとめ

| 技術 | 目的 | 代表例 |
|---|---|---|
| 共通鍵暗号 | 高速な暗号化・復号 | AES |
| 公開鍵暗号 | 安全な鍵交換、デジタル署名 | RSA, ECC |
| ハッシュ関数 | 改ざん検知、パスワード保存 | SHA-256, bcrypt, Argon2 |
| TLS/HTTPS | 上記を組み合わせた通信の暗号化 | - |
